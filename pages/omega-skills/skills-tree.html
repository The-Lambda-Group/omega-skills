The Skills Tree

The public skills in this repo form a Skills Tree. Each skill names its Parent Skill in its first body line; each parent names its Child Skills. The links are reciprocal so the tree is navigable from either end — an agent that starts at the root learns what exists below it, and an agent that lands mid-tree (skills are matched on their description, so this is the common case) learns to go up first.

The parent line

Every non-root skill opens its body — immediately after the frontmatter, before the <h1> — with:

**Parent skill: `omega-navigation`.** If you have not invoked `omega-navigation` yet, invoke it
first — it establishes how to find your bearings in a workspace — then come back here.

The root carries no parent line. It declares itself the root and lists its children under a ## Children heading.

Advisory, not enforced

Nothing blocks an agent that invokes a child without its parent — the line tells it to go read the parent and return, and that is all. There is no loader check. This is deliberate: the skills are Markdown read by a model, and a hard gate would need machinery in the skills loader that does not exist and that this convention does not justify.

Shipping a change

These skills are baked into the agent sandbox image at /opt/omega-skills/skills, and buildOpencodeSpec points opencode's skills.paths there — so a skills change ships as a sandbox image rebuild, never a runtime edit. See omega-ai-agent-service/pages/agent-service/sandbox-runtime.html. To iterate locally without a deploy, stage your checkout with OMEGA_SKILLS_DIR and run ./scripts/local-dev.sh — see that repo's local-development.html, "Iterating on a skills change".

A skill only works if it is invoked

Skills are matched by their description and read only when the agent invokes the skill tool. Nothing loads one automatically, and the parent line above is advisory text, so an agent can — and does — write to a page without consulting anything.

MEASURED 2026-09-04, five in-cluster runs against the same fixture and prompt: the agent consulted omega-database-pages in 3 of 4 runs where it was available. Every run that consulted it produced a correct result; the run that did not reproduced the exact bug the skill exists to prevent — a uuid-named orphan row.

What makes it reliable is the baked agent instructions, not the skill itself: agent-docs/CLAUDE.md in omega-ai-agent-service is copied to /workspace/CLAUDE.md (the sandbox's working directory) and is read at session start. Its ## Skills section names the trigger for each skill. When you add a skill here, add its trigger there too — otherwise it ships as a file agents may never open.

Adding a skill

  1. Create skills/<name>/SKILL.md with name + description frontmatter. The description is what an agent matches on — write it as "use when…", not as a title.
  2. Add the parent line as the first body line.
  3. Add the skill to its parent's ## Children list, with one line saying when to use it.
  4. Add it to the tree in this page and in the repo README.md.
