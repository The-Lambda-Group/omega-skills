Omega Public Skills — Terms

Omega Public Skills
Generic, public Hermes-agent skills for working with OmegaAI via the query-omega MCP — this repo, omega-skills (omega-navigation, omega-components, omega-packages, omega-devcontainers). Grounded in this repo's README.md ("Generic, public Hermes agent skills for working with OmegaAI via the query-omega MCP").
Skills Tree
The parent/child structure over this repo's public skills. Every skill names its Parent Skill; every parent names its Child Skills. The links are reciprocal so the tree is navigable from either end. See The Skills Tree.
Root Skill
The one skill in the Skills Tree with no Parent Skill: omega-navigation. It establishes workspace orientation — know the Home and Session workspaces, read the memory in the Home workspace's Notes/README, ls the Session workspace's root, read its README, describe an unfamiliar page — which every Child Skill assumes has already happened.
Parent Skill
The skill a Child Skill names in its first body line, instructing the agent to invoke it first and come back. Advisory: nothing enforces the order.
Child Skill
A skill named in a Parent Skill's ## Children list, with one line saying when to use it. Every skill except the Root Skill is a Child Skill.
Coordinator
In development work, the agent talking to the user. It holds the conversation and dispatches Dev Subagents; it never reads or writes the Dev Volume itself. See omega-dev-coordinate.
Dev Subagent
A fresh session of the Dev Machine's worker, given one self-contained job by the Coordinator — explore, write a spec, write a plan, revise, carry out one task, probe — and replying with a report.
Dev Machine
Three blocks in the user's workspace: a Devcontainer whose mounts attach the Dev Volume, and a worker service account whose sessions boot that Devcontainer. See omega-dev-machine.
Dev Volume
The Dev Machine's Volume: persistent disk holding the repositories (the Repos directory) and the specs and plans (the Plans directory, <mount>/.omega).
Dev Machine Record
The note page named Dev Machine that <root>/Notes/README links, at <root>/Notes/Development/Dev Machine (the path a default record is written at) or inside another folder of the user's notes that the README links, naming the Dev Machine's Workspace, Devcontainer, Devcontainer JSON, Volume, Mount, Worker, Repos and Plans.
Plans Index
The database page named Plans that <root>/Notes/README links, at <root>/Notes/Plans or inside a folder of the user's notes such as <root>/Notes/Development/Plans: one row per plan, keyed by Plan Name, indexed by Created, with Status, Repository, Base, Spec, Plan and Branch, and a "Most recent" view.
Revise Goal
The goal a Coordinator sets on its own session, through agent_goal, when new work starts: the commander kit's default.txt loop worded for omega-dev-revise — revise the plan on a loop until it is exact, with no development. It ends with a State: line, not a judge. See omega-dev-coordinate.
Phase Goal
The Revise Goal or Development Goal a Coordinator holds while a phase skill (omega-dev-brainstorm, omega-dev-plan, omega-dev-revise, omega-dev-develop) runs; each skill's Coordinator section says which, and omega-dev-retro clears it. See omega-dev-coordinate.
Development Goal
The goal that replaces the Revise Goal when the user tells a Coordinator to develop an approved plan: the commander kit's develop.txt loop worded for omega-dev-develop — develop, revise and handle surface events until the tests are comprehensive. A Coordinator holds exactly one of the two goals while it works. See omega-dev-coordinate.
Dev Subagent Watch
The Session Subscription a Coordinator registers on each Dev Subagent session she dispatches (qo agent watch), so its Run End wakes her; it never replaces reading the reply. See omega-dev-coordinate.
Plan Name
YYYY-MM-DD-<topic>, unique in the Plans Index; it names the spec and plan files and, without the date, the branch feat/<topic>.
Plan-only devcontainer
A second devcontainer block that mounts the same Dev Volume as the Dev Machine's Devcontainer, created for one plan that needs more than the Dev Machine's image, named in every Dev Subagent job of that plan, and deleted when the plan's loop ends; the Dev Machine's own Devcontainer is left unchanged. See omega-dev-coordinate.
